## Model the decision

A review queue should record why a conversation was included. In this standalone example, each item has an identifier, a short explanation, and one of three statuses.

```typescript title="review-queue.ts"
type ReviewStatus = "new" | "reviewed" | "dismissed";

type ReviewItem = {
  id: string;
  reason: string;
  status: ReviewStatus;
};

const queue: ReviewItem[] = [
  {
    id: "sample-001",
    reason: "Asked how to keep track of follow-ups after a demo",
    status: "new",
  },
];

function pendingItems(items: ReviewItem[]) {
  return items.filter((item) => item.status === "new");
}
```

The `reason` should be readable without opening the implementation. It is useful to a reviewer; a number such as `0.92` needs more context.

## Make failures understandable

<BlogCallout title="Keep the item available">

If saving fails, keep the reviewer’s decision visible and let them try again. Do not silently move the item to another list.

</BlogCallout>

```text title="Example error"
Could not save your review. Your changes are still here. Try again.
```

## Keep long lines inside the code block

The following example intentionally uses one long line so you can check horizontal scrolling on a phone.

```typescript title="long-line.ts"
const explanation =
  "The person explicitly described losing track of follow-ups after product demos, asked for a simpler workflow, and mentioned that their current notes are spread across a spreadsheet and two inboxes.";
```

A code block without a language still needs readable spacing and a working copy action:

```
new -> read the context -> decide -> save the review
```
