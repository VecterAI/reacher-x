Open a candidate who was marked Hired and look at the stored status. You will find `converted`, not `hired`. A customer can carry that same stored value. The workspace tells the app what the value means to the person using it.

That is the first thing to understand before you change a use case in ReacherX. The app does not need a new table for every kind of person a user might look for. One shared definition supplies the labels and gives the agent its context for the job.

## One definition, many meanings

[shared/lib/workspaceUseCases.ts](https://github.com/VecterAI/reacher-x/blob/main/shared/lib/workspaceUseCases.ts) holds the definitions. The `recruiting` entry carries these stage labels:

```ts
stageLabels: {
  new: "Sourced",
  contacted: "Contacted",
  in_progress: "Interviewing",
  converted: "Hired",
  archived: "Archived",
},
```

Suppose you want a different word for Interviewing. Change the label, then check the places that display it. Keep `in_progress` as the key. Replacing a stored value would touch the schema and every reader and writer of that field.

The same entry also defines entity names, route slugs, and page labels, plus a `promptContext` with `searchIntent`, `qualificationLens`, `outreachGoal`, and `successDefinition`. Those lines tell the agent what this use case is for. Looking for someone to hire calls for different evidence than looking for someone who might buy a product.

This command finds the code that reads the labels and the prompt context:

```sh
rg 'stageLabels|promptContext' shared features convex
```

## From definition to screen to mutation

[shared/hooks/useActiveUseCaseLabels.ts](https://github.com/VecterAI/reacher-x/blob/main/shared/hooks/useActiveUseCaseLabels.ts) resolves the active definition. A loaded workspace wins. While it loads, the hook falls back to a cached value, then to the server-provided value, then to the product default. Workspace setup keeps its own draft choice.

If a hiring workspace shows customer labels, check that resolved key first. Do not fix it by hard-coding "Candidates" into a component. `PipelineTimeline.tsx`, the profiles, and the card menus all need to agree on the active use case.

Stages change through `updateProspectStatus` in [convex/prospects.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/prospects.ts). The mutation checks ownership, writes `status` and `pipelineStage`, and records a timestamp for the new stage. Archiving schedules a pause of automated work, and unarchiving resumes it. You must unarchive a person before you can move them to a later stage.

## From definition to agent instructions

[convex/agents/prompts.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/agents/prompts.ts) turns the definition into agent instructions. The planning and qualification paths in [convex/agents/internal.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/agents/internal.ts) read the same use case context directly, and [convex/agents/outreach/index.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/agents/outreach/index.ts) builds the outreach prompt from it.

Your workspace description supplies the specific requirements. Saved memories add standing instructions, and [convex/lib/learningCore.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/lib/learningCore.ts) includes the use case in its learning context. Changing context does not retrain the model. The [memory article](/blog/how-reacherx-memory-works) explains what is stored and retrieved.

## What to check after a change

Ask for a plan in a hiring workspace, a partnership workspace, and a fresh setup draft. Does the agent still ask for buying intent in a recruiting workspace? Then check the list, the profile, the stage menu, the success page, and Analytics for label mix-ups.

The use-case label coverage in [tests/ui-consistency-regressions.test.ts](https://github.com/VecterAI/reacher-x/blob/main/tests/ui-consistency-regressions.test.ts) and the prospect status coverage in [convex/readModelStripes.integration.test.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/readModelStripes.integration.test.ts) protect nearby behavior. Include an older workspace with no use-case key and an archived person when your change touches those paths. Read the [generated Convex guidelines](https://github.com/VecterAI/reacher-x/blob/main/convex/_generated/ai/guidelines.md) before changing the mutation. The [architecture overview](/blog/how-reacherx-agent-works) connects this path to the rest of the app.
