A person can appear in a search and still be a bad fit. Qualification is the step that checks the available information against what the workspace actually needs, and it is more demanding than it looks.

This step sits between discovery and enrichment. It can load the evidence posts it needs into context before deciding, so "before enrichment" never means "score a name without looking at anything".

## Start with what the workspace asked for

Read [convex/workflows/qualification.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/workflows/qualification.ts) and [convex/lib/qualificationCore.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/lib/qualificationCore.ts). The workflow loads the prospect and the workspace, confirms the work is still valid, pulls in learning context, and hands everything to the core evaluator.

The evaluator does not chase a vague wish to "find good leads". It works through structured criteria. Each criterion is required, preferred, or an exclusion. The result carries verdicts, a confidence level, a rationale, and references to the sources that back it.

The shape of a criterion changes what counts as proof. "Has discussed this problem" and "works as a designer" need completely different evidence, and a job title can only ever support the second one.

## Judgment and arithmetic stay separate

The model interprets evidence. [convex/lib/qualificationScoringCore.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/lib/qualificationScoringCore.ts) reconciles its verdicts and computes the score in plain TypeScript.

The score has four parts.

| Component       | Maximum |
| --------------- | ------- |
| Profile fit     | 30      |
| Signal quality  | 30      |
| Intent strength | 25      |
| Recency         | 15      |

The total is a ranking built from the workspace's criteria and the evidence behind them. It is not a probability that someone will buy or reply, and treating it like one is a mistake.

## A high score cannot rescue missing evidence

The final condition is explicit, and it reads almost like a refusal:

```ts
qualified:
  breakdown.total >= args.threshold && hardFailureCriterionIds.length === 0,
```

The score has to clear the threshold, and no hard failure can be present. A required criterion that is unmatched blocks qualification. A confidently matched exclusion blocks it. Likely-bot detection blocks it. So does having no verified evidence at all.

Missing evidence gets special treatment. `reconcileQualificationCriterionResults` fills absent criterion results with `unknown`, and a criterion that demands activity evidence gets downgraded to `unknown` when someone claims a match without pointing at a source.

That rule exists because AI answers can sound confident while pointing at nothing. Raising the score threshold would not fix that. Checking the evidence before scoring does.

The helpers and tests for evidence handling sit next to the scoring code. Read [convex/lib/qualificationEvidenceCore.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/lib/qualificationEvidenceCore.ts) for source handling, and [convex/lib/qualificationDiscoveryEvidenceCore.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/lib/qualificationDiscoveryEvidenceCore.ts) for the case where the original search result contributes evidence.

## Save a result only if the work is still current

The workflow uses a stored workflow ID and state checks so that stale or duplicate work is never treated as a fresh result. A saved qualification records its activity and a memory event, then starts enrichment for anyone who qualified.

There is one distinction worth protecting: a provider failure is not the same as a valid decision that someone does not fit. The recovery code keeps them apart. Never "fix" an outage by marking every affected person disqualified.

For a contribution, capture the criterion, the evidence, the expected verdict, and the actual verdict. Read [convex/lib/qualificationScoringCore.test.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/lib/qualificationScoringCore.test.ts), [convex/qualificationDiscoveryEvidence.integration.test.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/qualificationDiscoveryEvidence.integration.test.ts), and [convex/qualificationFailureRecovery.integration.test.ts](https://github.com/VecterAI/reacher-x/blob/main/convex/qualificationFailureRecovery.integration.test.ts) for the boundaries that matter.
