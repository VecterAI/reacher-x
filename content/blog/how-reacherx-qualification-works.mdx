A person can appear in a search without being a good match. Qualification is the step that checks the available information against what the workspace actually needs.

In the normal discovery path, qualification comes before the full enrichment workflow. It can still read and hydrate evidence needed to make the decision. “Before enrichment” doesn't mean “score a name without looking at anything”.

This article follows v4 beta at commit `8ea2662`.

## Start with the workspace's requirements

Read [convex/workflows/qualification.ts](https://github.com/VecterAI/reacher-x/blob/8ea266282d045c8d83764be86c561ef8010fa661/convex/workflows/qualification.ts) and [convex/lib/qualificationCore.ts](https://github.com/VecterAI/reacher-x/blob/8ea266282d045c8d83764be86c561ef8010fa661/convex/lib/qualificationCore.ts). The workflow loads the prospect and workspace, checks whether the work is still valid, retrieves learning context, and calls the core evaluator.

The core works with structured criteria rather than a vague request to find a good lead. Each criterion can be required, preferred, or an exclusion. The evaluation returns verdicts, confidence, a rationale, and source references.

A required criterion such as “has discussed this problem” needs different evidence from “works as a designer”. A job title cannot prove the first one.

## Keep judgment separate from arithmetic

The model interprets evidence. [convex/lib/qualificationScoringCore.ts](https://github.com/VecterAI/reacher-x/blob/8ea266282d045c8d83764be86c561ef8010fa661/convex/lib/qualificationScoringCore.ts) reconciles the results and calculates the score in ordinary TypeScript.

The score has four components:

| Component       | Maximum |
| --------------- | ------- |
| Profile fit     | 30      |
| Signal quality  | 30      |
| Intent strength | 25      |
| Recency         | 15      |

Those numbers are not a probability that someone will buy or respond. They are a ranking built from the workspace's criteria and supported evidence.

The final condition is explicit:

```ts
qualified:
  breakdown.total >= args.threshold && hardFailureCriterionIds.length === 0,
```

A high total cannot cancel a hard failure. A required criterion must be matched. A sufficiently confident matched exclusion blocks qualification. Likely-bot detection and having no verified evidence can also block it.

## Missing evidence stays missing

`reconcileQualificationCriterionResults` fills absent criterion results with `unknown`. For non-exclusion criteria that require activity evidence, a matched or partial verdict without source IDs is downgraded to unknown.

That rule is important when an AI response sounds confident but doesn't point to a source. Raising the score threshold would not solve the underlying problem. The evidence needs to be checked before scoring.

The evidence-related helpers and tests sit beside the scoring code. Follow [convex/lib/qualificationEvidenceCore.ts](https://github.com/VecterAI/reacher-x/blob/8ea266282d045c8d83764be86c561ef8010fa661/convex/lib/qualificationEvidenceCore.ts) when investigating source handling, and [convex/lib/qualificationDiscoveryEvidenceCore.ts](https://github.com/VecterAI/reacher-x/blob/8ea266282d045c8d83764be86c561ef8010fa661/convex/lib/qualificationDiscoveryEvidenceCore.ts) when the original search result should contribute evidence.

## Save a result only if the work is still current

The workflow uses a stored workflow ID and state checks to avoid treating stale or duplicate work as a fresh result. It records qualification activity and a memory event, then starts enrichment for eligible qualified results.

A provider failure is different from a valid decision that someone doesn't fit. The recovery code and failure metadata preserve that distinction. Don't “fix” an outage by marking every affected person disqualified.

For a contribution, capture the criterion, evidence, expected verdict, and actual verdict. Read [convex/lib/qualificationScoringCore.test.ts](https://github.com/VecterAI/reacher-x/blob/8ea266282d045c8d83764be86c561ef8010fa661/convex/lib/qualificationScoringCore.test.ts), [convex/qualificationDiscoveryEvidence.integration.test.ts](https://github.com/VecterAI/reacher-x/blob/8ea266282d045c8d83764be86c561ef8010fa661/convex/qualificationDiscoveryEvidence.integration.test.ts), and [convex/qualificationFailureRecovery.integration.test.ts](https://github.com/VecterAI/reacher-x/blob/8ea266282d045c8d83764be86c561ef8010fa661/convex/qualificationFailureRecovery.integration.test.ts) for the relevant boundaries.
