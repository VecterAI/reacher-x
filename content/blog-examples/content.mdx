3. Read the context before reaching out.

## Code you can copy

The filename stays above the code. Long lines scroll inside the block rather than widening the article.

```typescript title="audience.ts"
const audience = {
  role: "Founder",
  context: "Building a B2B product",
  need: "Looking for a simpler way to find customers",
};

const brief = `${audience.role} · ${audience.context} · ${audience.need}`;
console.log(brief);
```

Use inline code such as `audience.role` for names that belong in code.


## Notes without the clutter

<BlogCallout title="Read the project guidance">

Check the repository's agent instructions before changing the code. They explain where shared components belong and which helpers already exist.

Keep a change focused enough that someone else can understand why it was made.

</BlogCallout>

A note should sit close to the instruction it explains. It should not feel like a second page inside the article.
